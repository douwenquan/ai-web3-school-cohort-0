# Showcase and Retrospective — Pay-per-Use Research Agent

> 项目复盘：问题、主流程、验证证据、风险与方向

---

## 项目解决的问题

链上研究者需要从多个数据源获取信息，但：
- **高质量数据需要付费** — 免费数据有限
- **手动采购成本高** — 每次需要手动操作和记录
- **过程难以审计** — 无法证明「用了什么数据、花了多少钱、结论怎么来的」

## 最小可验证主流程

```
研究问题 + 预算 → 免费数据 → 付费数据(402) → 预算校验 → USDC支付 → 报告 → 审计追踪
```

✅ 本地可运行，E2E 测试通过

## 最重要的验证证据

| 证据 | 说明 |
|------|------|
| HTTP 402 支付流程 | 付费数据源返回 402 → Agent 创建支付收据 → 重试 → 数据解锁 |
| 预算策略强制 | 后端确保不超过用户设定预算 |
| 支付收据 + 哈希 | 每次支付生成收据，数据/报告生成 SHA-256 哈希 |
| Base Sepolia USDC | 可选真实测试网转账 |

## 关键技术决策

| 决策 | 理由 |
|------|------|
| 确定性计划器（非 LLM） | Demo 稳定性优先，避免 LLM 不可预测性 |
| 微单位 USDC 计算 | 避免浮点精度问题 |
| 双模式支付 | 模拟模式可离线演示，真实模式展示 Web3 能力 |
| monorepo | 清晰分离各服务职责 |

## 关键风险

| 风险 | 缓解 |
|------|------|
| 确定性计划器 vs 真实 LLM | 架构支持替换，接口已定义 |
| 数据供应商是模拟的 | 清晰标注边界 |
| USDC 支付需测试网环境 | 模拟模式作为默认 fallback |
